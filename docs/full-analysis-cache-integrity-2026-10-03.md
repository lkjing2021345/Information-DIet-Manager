# 完整分析缓存复用合同

日期：2026-10-03。本批仅收紧 `/analyze/run_full` 复用已完成缓存的边界，不调整评分公式、模型执行方式、取消语义、前端或历史记录格式。

## 确证问题

原复用路径在通过有限数值、JSON 深度和 Unicode 检查后，只看 `statistics_scope`、`statistics_version`、`analysis_status` 和 `pipeline_warning`。临时 SQLite 中先通过真实 API 与合成推理结果生成有效分析，再分别把其缓存改成只含这四个标记、`total_count=999`、与请求不符的窗口。三个请求都返回 200、`cached=true`，复制为新的 `completed` 任务，而新任务的 `input_count` 仍为 5；结果查询接口也返回这些不完整或自相矛盾的内容。推理仅执行最初一次，坏缓存未重算。

这证明有限 JSON 不等于满足当前业务合同。探针也验证合法缓存仍命中；没有声称普通数据采集一定会产生上述损坏，触发条件是已存的缓存内容不完整或不一致。

## 实现

新增独立模块 `src/hyh/full_analysis_contract.py`。`app.py` 仅导入校验函数，并在原来的缓存复用位置调用；继续先执行已有有限 JSON、深度和 Unicode 检查。

校验当前版本 2 实际发布的外层合同：

- 必需字段存在，版本为严格整数；`day`、窗口起止、条数上限、输入数及总数与本次快照一致。合法起止 `None` 必须显式存在，`False` 不可充当 0。
- 有数据时为 `ready`，空窗口为 `empty`；沿用原重复度指标名称；警告为 `None`，`cached` 为布尔值，生成时间为合法范围内的严格整数毫秒。
- 渠道和分类是字符串键到非负严格整数的映射，各自总和等于输入数。分类名称不增加新的词表限制。
- 情感计数使用当前 `Positive`、`Neutral`、`Negative` 标签，总和等于其有效样本数；比较数最多为 N−1，情感数最多为 N，极性数最多为情感数。
- 每个指标单独保留缺失语义：对应有效数为 0 时必须为 `None`；有观测时必须在原合法数值范围内，合法 0 保留。负面比例还需与负面条数/情感样本数一致；不凭空推算平均极性或模型分数。
- `quick_evaluation` 和 `full_report` 只检查外层为字典，空窗口也允许 `None`。不规定内部评分结构，不拒绝 `{}` 替身或合法的扩展字段。

无效缓存沿原路径重算，原缓存及历史保留。重算失败仍写入安全的 `failed` 任务并返回原有错误状态，不回退到坏结果；`force=true` 继续绕过缓存。未修改删除/恢复的修订检查、模型门锁和同步工作归属。
