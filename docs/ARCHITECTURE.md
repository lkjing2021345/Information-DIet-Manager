# 系统架构

## 1. 定位与边界

Information Diet Manager 是一个面向 Windows + Chrome、由用户在本机运行的本地优先软件系统。它把浏览器扩展、回环地址上的 FastAPI 服务、SQLite 数据库和 Vue 3 控制台组合起来，帮助个人回顾已经保存的页面记录，并按需查看近 7 天的实验性统计。

项目目前是**可本地运行的开发预览**。记录接收、分页查看、删除、备份/恢复、密钥分离和基本仪表盘链路属于当前软件骨架；文本分类、情感标签、相邻文本相似度及旧的综合评分属于实验分析链路，尚未通过真实模型准确性、训练效果或结论有效性验收。统计结果不能用于健康等级、心理状态或“信息茧房”诊断。

## 2. 组件关系

```text
┌──────────────────────┐
│ Chrome Manifest V3   │
│ content/popup/queue  │
└──────────┬───────────┘
           │ POST /collect（collector_token）
           ▼
┌──────────────────────────────────┐
│ FastAPI 本地服务                  │
│ src/hyh/app.py                   │
│ 认证、来源检查、限流、业务编排    │
└──────┬───────────────────┬───────┘
       │                   │
       │ SQLite 读写        │ 可选分析调用
       ▼                   ▼
┌───────────────┐   ┌────────────────────┐
│ 每用户 SQLite │   │ src/lsj 分析链路     │
│ 记录/缓存/版本 │   │ 分类/情感/相似度等   │
└──────┬────────┘   └─────────┬──────────┘
       │                      │
       └──────────┬───────────┘
                  ▼
        ┌─────────────────────┐
        │ Vue 3 + ECharts 前端 │
        │ frontend/            │
        └─────────────────────┘
```

统一启动入口位于 `scripts/run_backend.py` 和 `scripts/run_analysis.py`；`src/backend_api` 与 `src/analysis_engine` 提供稳定的转接入口，历史 `src.hyh` / `src.lsj` 路径保留作兼容。前端通过本机 HTTP API 访问服务，不把密钥写入 URL 或构建变量。

## 3. 数据流

### 3.1 采集与入库

1. 用户在 Chrome 扩展弹窗中配置本机 `/collect` 地址、采集密钥和排除域名，并显式开启采集。
2. 内容脚本只处理用户选择浏览的顶层 HTTP/HTTPS 页面；会移除表单及可编辑区域，清理 URL 凭据、片段和常见令牌参数，并截取受限长度的标题/正文。
3. 扩展把待发送记录放入本地队列。网络失败、401/403 或服务不可用时，记录留在队列中等待用户修正配置或重试；队列达到容量上限时拒收新增并显示累计拒收次数。
4. 后端核对回环来源、请求大小、字段契约和 `collector_token` 角色后，将记录写入当前用户的 SQLite 数据库。页面地址按清理后的 URL 去重，因此记录数不等于访问次数、阅读时长或完整浏览历史。

### 3.2 查看、管理与备份

管理员界面使用独立的 `admin_token`。前端连接后从 `/items` 以游标分页读取记录，每页默认 50 条；记录抽屉和首页只展示已保存快照。删除、全部清空和备份/替换恢复属于管理操作，服务端在事务和版本检查下执行，并清理受影响的分析缓存。

备份是带格式版本和 SHA-256 校验的明文 JSON，不包含密钥、扩展队列或分析历史。恢复会重新生成内部 ID、创建时间和向量，因此是逻辑数据恢复，不是 SQLite 文件级迁移。备份和恢复有条数、字节数、字段及超时边界，失败应整体回滚。

### 3.3 仪表盘与分析

前端只在用户显式点击分析按钮时请求 `/dashboard/visualization?days=7&force=true`。后端在一个 SQLite 读取快照中确定时间窗口和可用记录，返回带 schema/version、有效数量、缺失状态和日趋势的可视化数据。没有数据、样本不足、分析不可用和分析失败分别表达，缺失指标不补零。

可选分析会调用 `src/lsj` 中的分类、情感和相似度实现。模型任务使用独立锁和有限的并发/容量边界，分析期间采集和删除可以继续；当删除或恢复导致数据版本变化时，旧结果会被丢弃并返回可识别的冲突状态。真实模型依赖、模型文件、训练数据和推理效果仍需单独验收，不能从合成契约测试推导出生产准确率。

## 4. 认证与运行时约束

- 服务默认只监听 `127.0.0.1`，前端只允许配置回环 API 地址；不要把服务暴露到公网或通过远程代理转发。
- `collector_token` 只能提交记录和检查自身会话；`admin_token` 才能读取、管理、导出和分析数据。两把密钥由服务启动时生成，前端管理密钥只保存在当前页面内存。
- 数据库默认位于当前 Windows 用户的 LocalAppData 目录，密钥文件与数据库相邻。显式 `IDM_DB_PATH` 应指向私有 NTFS 路径；同一数据库只允许一个 IDM 服务进程。
- 采集、管理、导入、导出和恢复均有请求体大小、读取期限、并发或数据库锁边界。错误应返回明确的 4xx/5xx 契约，不把失败伪装成空数据或成功结果。
- 分析历史采用有界保留：最多保留最近 500 个终态任务和 365 条运行记录；排队中/运行中的任务不参与清理，超出范围的旧缓存允许重新计算。
- 离线训练检查日志只记录字段、长度和哈希摘要，文件日志按 5 MiB、保留 3 个轮转文件；显式导出的错误样本文件仍可能包含原文，应按敏感数据保存和删除。
- 备份是明文文件，SQLite 和下载的备份没有应用层加密；系统不防御同一用户权限下的恶意进程、已被控制的浏览器或操作系统。

## 5. 当前稳定层与实验层

| 层级 | 当前可描述的能力 | 仍需验证的部分 |
| --- | --- | --- |
| 稳定基础 | 本地采集/导入、SQLite 保存、游标分页、基础仪表盘、单条/全部删除、备份/恢复、密钥分离、设置入口 | 更广泛浏览器/系统兼容性、逐站授权、保留周期和长期性能 |
| 实验分析 | 按需生成分类、情感、相邻文本相似度和部分趋势统计；界面区分缺失、样本不足和失败 | 真实模型推理、训练/评估、准确性、偏差、样本量、可重复性和任何健康/心理结论 |
| 历史接口 | `/analyze/run`、`/dashboard/summary`、`/analyze/run_full` 等兼容接口 | 旧综合评分和完整模型环境不应作为当前产品承诺 |

前端的科技风配色、玻璃卡片、动效、四图布局、主题控制和右侧抽屉是已批准的产品设计资产。后端或质量迭代不应通过重做界面来解决问题；界面改动必须另行明确授权。

## 6. 验证入口

验证必须区分静态/契约测试、真实浏览器测试和真实模型推理：

- Python：`python -m pytest src/hyh/tests src/lsj/tests scripts/tests -q`，使用临时数据库和合成密钥。
- 扩展单测：`node --test chrome-extension/tests/*.test.cjs`。
- 扩展真实浏览器：安装锁定依赖和 Playwright Chromium 后运行 `npm --prefix chrome-extension run test:e2e`，设置隔离的 `IDM_TEST_PYTHON`。
- 前端单测、构建和真实浏览器生命周期测试位于 `frontend/`，但这些检查验证的是界面/接口行为，不等于模型推理验收。
- 依赖锁、仓库卫生、运行时最小验收和当前未闭环事项分别见 `docs/python-locks-2026-10-03.md`、`docs/repository-hygiene-2026-10-03.md`、`docs/minimal-runtime-acceptance-2026-10-03.md` 和 `docs/quality-status-2026-10-03.md`。

任何“已完成”表述都应同时说明检查类型、使用的合成/真实数据和未覆盖范围。当前架构可以支撑本地开发预览，但还不构成云端多用户服务或经过真实模型验收的健康/心理分析产品。
