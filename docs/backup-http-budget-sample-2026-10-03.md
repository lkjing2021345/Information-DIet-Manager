# Windows 真实 HTTP 备份边界单次观测

测量源码为 `5f23c9a00235e033e6695f8b3a0515914caab0e1`，使用完整锁定的 Windows Python 3.12 测试环境，不是独立的最小运行环境。

三个样本分别运行自有本机服务和临时 SQLite，使用随机合成能力密钥、禁用代理及模型联网，不接触个人数据。所有输入逐条通过当前 `IngestItem` 验证后直接 SQL 种入：1800/2000 字符代表可恢复的合法历史正文，正常采集的 1000 字符规则未改变。

| 10000 条 × 1800 ASCII 正文 | 200，19820155 字节 | 55.281 | 118.910 | 0.4392 |

成功包为 18.902 MiB，约为 20 MiB 上限的 94.51%；全部 10000 条业务字段、规范 JSON 摘要、传输长度和摘要均核对。字节超限样本预计算包为 21820155 字节，但没有将其当作实际导出文件；实际响应只有安全拒绝信息。三个服务请求后健康检查均为 200，正常退出码为 0，全部专属进程、数据库和下载已清理。

测量通过服务内 `os.getpid()` 确认实际运行进程，再调用 Windows `GetProcessMemoryInfo`；没有误测虚拟环境外层启动器。峰值是服务整个生命周期的内核工作集峰值，含启动和退出；约 10ms 的采样峰值更低，未拿它替代内核峰值。客户端边读边写，待服务退出后才解析完整 JSON，所以服务数字不含客户端解析内存。

输入数据库合计 64282624 字节；未触及探针设置的 512 MiB 工作集观察阈值或每服务 60 秒观察期限。这些是探针保护，不是应用的硬资源限制。

每组仅单机单次且无并发，不能据此承诺 SLO、长期性能或最大内存；仍缺慢消费者、并发备份、慢盘、磁盘满、恢复峰值和真实模型负载。原始脚本与结果保存在忽略目录 `output/playwright/quality-20261003/backup-http-budget/`，不作为发行制品提交。
