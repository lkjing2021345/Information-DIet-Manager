# 分析历史读取与全局缓存完整性

## 修复前的实际问题

此前对 full/dashboard 缓存的非有限数字防御没有覆盖全部读取路径。使用新建临时 SQLite、真实 HTTP 路由和空窗口任务复现了以下行为，未读取个人数据库，也未运行模型：

- `/analyze/jobs/{id}` 与 `/analyze/result/{id}` 读取旧 `result_payload` 或 `metrics_json` 中的 NaN、Infinity、-Infinity、1e999 时返回 200；序列化把这些非法数字变成 null，任务仍显示 completed。
- `/analyze/history` 对频道计数字段有同样问题；SQLite REAL 列中的正负无穷也被静默转成 null。破损 JSON 同样被当成正常缺失值。
- 300 层嵌套可以通过标准库 JSON 解析与严格编码，却触发 HTTP 响应序列化错误。孤立 Unicode 代理字符作为字符串值或对象键，也会产生同类通用 500。
- `/dashboard/summary` 与 `/analyze/run` 仍会复用被污染的全局缓存，返回 `cached: true` 和 null 频道计数，并把非有限数字重新写进 daily 投影；运行入口还会追加受到污染的历史。

新测试先记录这些失败，再验证修复；不是通过删除断言或把坏数据改成缺失值取得通过。

## 读取合同

新增小型 `analysis_json.py`，供分析缓存及历史共用。它拒绝非有限浮点数、非法 JSON、不能编码为 UTF-8 的字符串值和对象键，以及超过 **64 层容器**的结构。顶层对象或数组算第 1 层，对象与数组混合嵌套按同一规则计数；标量不增加容器层数。

NaN 和 Infinity 在解析时拒绝；1e999 这种语法合法但溢出的数字也拒绝。深度验证使用显式遍历，不依赖 Python 或响应框架恰好采用的递归限制。SQL NULL、JSON null、合法有限的零、中文和合法 emoji 继续保留。

历史记录不能自动重算后冒充原结果。三个历史读取入口遇到无效存储内容统一返回 HTTP 409：

```json
{"detail":{"code":"stored_analysis_invalid","message":"Stored analysis data is invalid."}}
```

错误没有原始报告、字段值或异常详情；读取不删除历史、不修改任务状态、不回写数据库。历史列表当前采用整次请求返回 409 的策略，不悄悄遗漏其中的坏记录。未完成任务原有的状态冲突、不存在任务的 404，以及合法空值的读取行为保留。

缓存可以重新计算：全局 summary/basic 以及 full/dashboard 共用严格缓存读取，坏缓存视为未命中。全局统计从现有 items 重算，重写可信 daily 投影并记录新的结果；旧坏历史原样保留。新的干净缓存随后可以正常复用。

full 的新报告发布也使用同一校验，位置在既有结果事务保存点内。不能先把超深或非法 Unicode 报告写成 completed，再让历史读取拒绝它；校验失败沿原有安全 500/failed 路径处理，回滚本次报告与历史写入。恰好 64 层的合法新报告可以发布并成功读回。

本轮没有修改前端模板、样式、布局、动效或模型算法，也没有读取时的数据迁移。

## 验证

新增历史完整性回归覆盖以下场景：

- 四种非有限 JSON 数字、损坏 JSON、300/2000 层嵌套、SQLite REAL 正负无穷。
- 混合容器第 63/64 层接受、第 65 层拒绝的实际 HTTP 边界。
- 孤立代理字符的字符串值与对象键拒绝，合法中文/emoji 保留。
- 全局两个入口按真实 items 重算、保留旧历史，full/dashboard 的有限但 65 层旧缓存重新计算并恢复正常命中。
- 正常 null、真实零和未完成任务状态不被误判；历史读取前后相关表内容完全一致。
- 新 full 报告写入与读取采用同一深度和 Unicode 合同，拒绝时留下可查询的失败任务，不留下成功历史。

最终新增文件 **68 项通过**；连同旧统计、分析并发和查询边界的相关回归共 **180 项通过**。这些数量是包含关系，不应相加计算独立测试总数。差异空白检查通过。

full/dashboard 的缓存回归使用明确的合成推理输出，验证的是实际 HTTP、SQLite、缓存与统计流程，不证明模型推理或准确率。其他基础统计和空窗口场景不需要模型。

本轮的完整项目回归与远端 CI 由整合提交核对。本机仍有既有 Starlette/httpx 弃用警告。

## 剩余边界

这些检查保护 JSON 数字、编码和结构深度，不能代替报告业务字段模式、模型准确性或所有历史版本的迁移验证。完整语义 schema 验证、坏历史的用户修复流程和更广的数据恢复矩阵仍需单独设计；不能把本轮通过解释为所有损坏数据都会得到可信结果。
