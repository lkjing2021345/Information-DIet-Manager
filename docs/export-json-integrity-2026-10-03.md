# 普通导出的标签与元数据完整性

## 修复边界

`GET /export/lsj` 的 `analysis` 与 `raw` 两种视图都包含 `tags` 和 `meta`。旧导出辅助函数把这些字段中无法解析的 JSON 转为 `None`，还忽略了 SQLite BLOB 中合法的 UTF-8 JSON。导出因此可能返回 `200`，但相应字段已经变成 JSON `null` 或 CSV 空单元格，调用方无法区分实际缺失和解析失败。

本批让这两个字段使用记录列表已有的严格 JSON 读取器。SQL `NULL`、JSON `null` 和合法的历史 JSON 对象、数组、标量继续保留；字节 JSON 也按其内容读取。语法错误、非有限数、无法解析的字节编码、孤立 Unicode 代理字符及超过 64 层容器的内容明确失败，由原导出错误映射返回固定 `409`。未增加当前采集 schema 的形状约束，因此不会把合法但形状较旧的值强行改成空值。

后续复核更正了原文“非法 UTF-8 必须拒绝”的过宽表述：共享读取器使用 `json.loads()` 的字节编码识别，除 UTF-8 外，合成探针中的带 BOM UTF-16 / UTF-32 JSON BLOB 也被正确解析。字节不能单独按 UTF-8 解码，不等于其 JSON 内容无效。本次仅更正文档，没有收紧合法历史数据的读取兼容性。

实测旧 CSV 还会把标量 `NaN` / `1e999` 输出为 `nan` / `inf`；JSON 和 JSONL 原有编码器已拒绝这些值。本次在三种格式的公共读取阶段统一拒绝非有限数。旧实现的 65、300、2000 层输入在本次探针环境中均成功导出；修复后统一遵守记录列表已有的 64 层边界。如果底层解析先触发 `RecursionError`，读取器也会包装成数据错误，而非进入通用存储错误分支；这条是代码路径保证，不是本次旧实现返回 `507` 的实测证据。

## 保持的行为

- JSON、JSONL、CSV 都先完整准备再返回成功；后续记录发现错误时关闭临时文件，不交付半份成功文件。
- 错误响应不包含字段内容、异常堆栈或路径；读取失败不改写数据库。
- 真实缺失仍是缺失；合法数值、布尔值、Unicode 与嵌套值保持原有序列化规则。CSV 的字典和数组仍编码为 JSON，标量和空值沿用现有单元格约定。
- 训练导出不包含 `tags`、`meta`，不因此额外拒绝无关字段。其筛选、去重、截断与文本清理保持不变。
- 本批不调整普通导出已有的标题/正文处理、资源预算、下载方式、前端或模型。
