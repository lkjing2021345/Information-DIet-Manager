# 2026-10-03 全局统计与旧分析接口修复

本轮处理旧 API 的数据口径、缓存和失败事务，不改前端源码。此前仪表盘已使用独立的记录快照和可视化接口，但旧 API 仍可被本地管理员或其他客户端调用，因此也需要保持可信。

## 已确认的问题与行为变化

- 库中保存 20 页后，旧 full 只分析 6 页，会把 6 写进同一天的 `stats_daily`；概要接口随后把局部数量当成全局数量。现在 `stats_daily` 只作为全局统计兼容投影，窗口分析写自身历史和任务；返回体明确标注 `all_saved_pages` 或 `analysis_window`。
- 仅比较最大创建毫秒无法识别同毫秒新增，也无法识别部分更新。新缓存结合数据库身份、变更版本、总量、最大 ID 和创建毫秒，拒绝旧版或窗口类型混淆的缓存。有效的全局概要缓存不在每次轮询时添加重复历史。
- 全局重复率统计规范化内容哈希的重复比例，披露有效哈希数量；没有哈希的记录不进入分母，空集返回 null。该比率不是相邻文本相似度，也不是重复访问次数。
- 缺省频道和显式 `unknown` 以前会在合并 SQL 分组时覆盖，导致分类数量总和小于总量。现在逐组归一并累加，缺省、空白和别名的混合输入不丢数。
- 旧 full 顶层统计不再把首条无前驱的比较、无效情感或缺失极性补成 0；按指标独立计算有效分母，披露比较、情感和极性数量。越界值不会通过裁剪变成有效值，空窗口的三项指标均为 null。
- 极大时间筛选值以前会触发 SQLite 整数溢出并返回 500；full 与两类导出接口现在沿用采集时间的合法毫秒范围，越界返回 422，反向区间返回 400。
- 旧分析缺少可选依赖时曾返回成功及全体中性数据；现在返回 503 和失败任务。完整样本条件不满足返回 422，意外异常返回 500；响应、任务和历史均不记录异常原文或堆栈。
- 失败处理曾可能回滚掉失败任务，或在成功记录写入一半时留下混合状态。现在以保存点回滚该次成功结果，再记录失败状态；底层介质本身不能写入时仍无法保证保存失败任务。

## 验证边界

测试使用临时 SQLite、合成记录和分析替身，覆盖窗口分析与全局概要交错、同毫秒新增、更新/删除/恢复、旧缓存、失败恢复、异常信息不外泄和结果部分写入的故障注入。真实模型权重、推理准确率与综合评分未验收。

本轮最终本地后端回归 **260 项通过**，其中新增 49 项；仍有 1 条 Starlette/httpx 弃用警告。有效分母测试使用合成 DataFrame 和替代评分器，实际执行 API 的统计聚合代码：6 条相同文本对应 5 次有效比较，重复率为 100%，类别仍计 6 条。

共享分析执行边界调整后的生产页面真实浏览器场景 **25 项通过**，包括鉴权、备份/恢复、分页冲突和原界面结构。前端无源码变更；生产构建仍保留超过 500 kB 的主包提示。GitHub CI 应以对应提交的 Actions 结果为准。

完整评分引擎仍属于实验功能，并保留原有完整样本要求。本轮修正 full 顶层摘要的测量分母，没有重写内嵌 quick/full 评分报告的预处理或证明其评分有效；调用方不能将实验报告解释为健康诊断。旧 full 仍串行持有数据操作锁；运行期间其他数据操作可能超过等待时间而返回可重试 503。仪表盘的独立可视化路径已采用短事务和版本校验，两者不能混称为相同并发能力。
