# 导入可选字段的完整性

旧版 `/import` 在逐行校验前把部分无效 `meta`、`tags` 转成 `None`，随后把该行计为成功。例如非对象的 meta 数组、坏 JSON 文本，以及对象／布尔／数字类型的 tags，会被静默丢弃。

本批只修改 `app.py` 的两个导入解析辅助函数：

- `tags` 若既不是空值、列表，也不是已有文字格式，抛出固定 ValueError，由现有逐行处理计入 `failed`。
- `meta` 若不是对象、合法空值，或其文字形式不是可解析的对象／null，抛出固定 ValueError。文件本身仍合法时，只拒绝该行。

导入仍返回 `inserted / duplicates / failed`，有效邻行继续入库，重复有效行仍计为 duplicates。无效字段不会变成缺失字段后计成功。错误响应只包含计数，不回显字段内容。整份文件无法解析时原有 `400` 行为不变。

兼容边界经旧版成功对照及修复后回归确认：缺省、None、空串、空白仍表示空值；`tags` 支持列表、JSON 数组文字、管道分隔与单个普通标签，保留 `[not-json` 这样的原有普通文字解释，不新增“以方括号开头必为 JSON”的规则。`meta` 保留对象、对象 JSON 文字以及 JSON 编码 `null` 的原空值行为。后者符合现有 Optional 字段语义；不把其他 JSON 标量或数组视为对象。

新增 `test_import_field_integrity.py` 共 35 项，使用真实 ASGI multipart 请求与临时 SQLite，无模型及个人数据。覆盖 JSON/JSONL 的无效类型、CSV 的非对象／坏 JSON meta、有效邻行和重复行计数、11 种合法字段表示在三种文件格式下的保存与回读，以及全部无效时已有记录不变。

- 旧版新增回归：**32 failed，3 passed，2.53 秒**。
- 修复后新增回归与既有文件解析边界：**43 passed，1 warning，2.93 秒**。警告为已有 Starlette/httpx 适配器弃用提示。
- `git diff --check` 通过。

本批没有修改字段长度限制、正文截断、写入事务、备份恢复或前端。这里是实际 HTTP 与数据库验收；真实浏览器、完整回归和精确提交 CI 由总验证记录。
