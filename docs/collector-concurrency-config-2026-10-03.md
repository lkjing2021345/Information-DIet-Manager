# 训练模型池并发配置的前置校验

两个训练收集器此前在构造模型客户端之后才创建 `asyncio.Semaphore(cfg.concurrency)`。纯替身客户端探针确认：并发值为 0 时客户端已经构造，生成调用等待没有许可的信号量，50 毫秒探针超时后取消；负数则在已经构造一个客户端后抛出 ValueError。没有网络或真实模型调用。该短探针不是长时间运行验收；上层任务超时仍可取消等待。

现在两个 `ModelPool.__init__()` 在创建任何客户端前检查全部传入配置对象：`concurrency` 必须是正整数，拒绝 bool。任意一项无效均使用固定 ValueError 文案，不泄漏配置值，也不会先为前面的合法项构造客户端。所有原有合法正整数继续支持，没有新增任意上限；默认值和其他配置不变。

这里校验的是模型池实际收到的配置对象。`parse_model_configs()` 现有的 `int(...)` 归一化语义没有改变，不能把这次修复描述为原始 JSON 配置的严格类型校验。

新增 `test_collector_concurrency_config.py` 共 26 项：双收集器覆盖 0、负数、整数值浮点数、非整数浮点数、两个布尔值，以及合法项之后出现坏项时不构造任何客户端；另验证 openai、anthropic、local 三种客户端替身以 1、3、10^9 的合法配置正常构造、生成和关闭。大整数对照仅验证没有人为上限，不表示建议或已验证如此规模的并发负载。
