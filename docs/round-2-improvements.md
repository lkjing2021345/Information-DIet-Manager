# 第二轮：可靠采集、输入契约与自动验收

日期：2026-09-24。基线：`511385a`。定位仍是 Windows + Chrome、每人本地运行的开源开发预览。

## 本轮结果

这轮集中修复“网页 → 扩展持久队列 → 本地 API → SQLite”的可信交付，并建立可重复运行的质量检查。没有把模型功能、完整浏览历史或企业级发布就绪当作已完成事项。

默认策略采用可调整的隐私优先方案：新安装关闭；已有有效开关保留；容量满时拒收新增、保留已有队列。两项偏好尚未获得明确答复，因此属于本轮实现选择，不记为用户已经确认的产品承诺。

## 修复清单与证据

| 问题 | 修改后的行为 | 验证方式 |
| --- | --- | --- |
| 并发入队相互覆盖 | 单一串行持久化通道，记录带稳定 ID | 100 条并发入队全部保留 |
| 上传旧快照覆盖期间新增记录 | 网络请求不占写锁；仅按已确认 ID 删除 | 上传中新增记录回归 |
| 清空后旧失败记录复活、暂停后继续发送 | 清空/设置变更取消在途请求；提交结果前核对操作代际 | 延迟成功/失败、暂停、改地址、真实弹窗暂停 |
| 四次重试后静默丢弃 | 保留记录，发送前持久化尝试次数和下次时间；退避重试 | 六次离线仍保留、重建 worker 状态、浏览器重启 |
| HTTP 200/空 JSON 被误判成功 | 验证非负整数确认字段、failed=0、inserted+duplicates=1 | 错误确认组合单元测试与真实浏览器 HTTP 200 `{}` |
| 永久拒绝不断重试 | 普通 4xx 暂停该记录，显示“需要处理”，可手动重试；408/429 可退避重试 | 422 隔离与恢复、429 延后 |
| 请求无限等待 | 单请求默认 10 秒超时，单批最多 20 条及约 20 秒预算 | AbortSignal 超时回归；预算在请求边界检查，最后一次请求可超过批预算 |
| 队满静默删除旧条目 | 拒收新增，保留旧条目，累计拒收次数 | 容量边界测试 |
| 旧配置/队列不可控迁移 | 单状态版本迁移，先写新键再删旧键；无效旧记录隔离；无效设置恢复默认并暂停 | 迁移、写失败、重启；新状态损坏时拒绝执行并保留原数据 |
| 静态页初次漏采 | document_idle 后主动调度 | 内容脚本测试与真实静态页面 |
| 入队失败仍记“已发送” | 只在持久化成功/本地去重确认后更新指纹 | 队满后同内容重试 |
| SPA 跳转漏采或错用旧 URL | 检测页面 URL 变化；忙碌期间保留待采标志；后台读取当前标签页地址 | 慢策略 + SPA 测试；真实 history.pushState → 两条数据库记录 |
| 内容脚本能读队列/改配置 | 存储限可信扩展上下文；控制命令只接受本扩展 popup；采集限顶层非无痕页 | 发送者、子框架、无痕、命令边界测试 |
| 隐私默认值与传输范围过宽 | 默认关闭、排除域名、回环硬排除、表单/编辑内容剔除、密码页跳过、常见秘密参数清理、只传本机、禁止重定向 | 回环/子域/尾点边界、真实表单与令牌清理 |
| 标题/时间/元数据边界不清 | 严格时间戳、标题去空白、标签数量/长度、meta 8 层/8192 UTF-8 字节限制 | API 边界测试，包含合法 emoji、非法 Unicode、非有限数 |
| 错误输入反射或响应序列化 500 | 422 仅保留 type/loc/msg，不回显 input/ctx | raw HTTP NaN/Infinity/孤立代理字符及敏感标记回归 |
| 非 URL 数据库约束失败误报 duplicate | 只忽略 url_hash 冲突；其他失败回滚并报错 | CHECK/NOT NULL、单条恢复和批量 items+embeddings 回滚 |
| 缺少稳定轻量测试入口 | 分离基础 API/测试依赖，固定直接版本；Windows CI 执行测试和浏览器链路 | 全新虚拟环境安装、pip check、工作流静态验证 |

## 复核发现与修复过程

初版完成后进行了独立只读复查和主执行者复核。复查额外发现并修复了：忙碌状态吞掉 SPA 调度、同步锁住暂停按钮、回环地址别名及 DNS 尾点绕过、损坏设置字符串被当成 true、缺失重试时间使记录永久等待。真实浏览器又发现 `sender.url` 在 SPA 后仍可能是原文档地址，已改为浏览器当前标签页地址并加入回归。

这里的交付语义是“至少一次尝试 + 服务端页面去重”，不是 exactly-once。服务端已提交但响应丢失时会重发；如果用户已经清空队列，服务端仍可能已收到请求。迁移后的队列不能直接由旧版扩展识别，暂不支持安全降级工具。

## 本地最终验收

| 层次 | 结果 | 证据边界 |

| Python API/静态契约测试 | 70 项通过 | 其中算法目录的 3 项是静态检查；模型结果用合成替身 |
| 扩展 Node 行为测试 | 36 项通过 | 状态机、竞态、持久化故障、消息来源、内容调度 |
| 实际扩展浏览器流程 | 10 个场景通过 | Windows、Chrome for Testing 151.0.7922.34、真实 FastAPI、临时 SQLite、合成页面 |
| 前端数据行为测试 | 10 项通过 | 沿用第一轮统计展示回归 |
| 前端生产构建 | 通过，有体积警告 | 主 JS 约 1.23 MB，gzip 约 410 KB；尚未拆包 |
| 新虚拟环境依赖一致性 | pip check 通过 | 不安装 torch/transformers/cntext/sklearn，不代表算法依赖完整 |

实际扩展浏览器场景：默认关闭、开启后采集已加载静态页、文本/参数最小化并真实入库、SPA 跳转、排除域名、密码页跳过、断网后浏览器/worker 重启恢复、异常 ACK 保留、422 手动恢复、同步时暂停与清空。弹窗 HTML 作为扩展页面操作；没有自动点击 Chrome 工具栏的原生弹窗按钮。

测试不使用个人浏览器配置，不写仓库内数据库，不下载模型。可复现命令见根 README。截图和机器可读结果在被忽略的 `output/playwright/round2/`；系统临时目录中的测试配置/数据库只含合成资料，保留用于诊断。

GitHub 工作流覆盖 Windows + Python 3.12 + Node 24；仅只读仓库权限，Actions 固定完整 SHA，旧任务取消、最长 20 分钟。托管执行状态应以当前提交的 Actions 页面为准，不能用本地通过替代云端成功。

测试过程保留了 Starlette 对 httpx TestClient 的弃用提示，没有屏蔽它。前端仍使用现有 Vite 8 beta；其稳定版本迁移、依赖漏洞治理不在本轮完成范围。

## 距离严格企业级发布仍缺什么

优先级是本项目的工程判断，不是外部认证分数。没有统一可量化的“企业级完成百分比”，也不需要为了这个本地产品先引入微服务或 Kubernetes。

| 优先级 | 领域与差距 | 下一项可验收的交付 |
| --- | --- | --- |
| 发布前阻断 | API 无配对认证，CORS 仍为宽泛规则；回环绑定不等于访问授权 | 扩展/界面与本地服务配对、严格 Origin/Host/权限边界、对应越权测试 |
| 发布前阻断 | 隐私生命周期不完整：没有逐站授权、后端删除/保留周期、可靠备份恢复和队列修复 UI | 数据导出/删除/恢复验收、排除规则与权限说明、敏感数据威胁模型 |
| 发布前阻断 | 仓库仍跟踪 SQLite 和根 node_modules，缺根许可证文件；发布资产不纯净 | 单独审计历史数据与第三方许可，清理当前仓库内容，由所有者选择许可证，再制作干净安装包 |
| 高 | 页面表按 URL 唯一，不保留访问事件及正文版本 | pages/visits 分离、稳定事件 ID、迁移/回滚/备份；明确统计定义 |
| 高 | 实验模型真实推理、训练、准确性和偏差未验收 | 固定模型版本/来源与数据集，离线基准、失败退化；继续避免健康/心理/茧房诊断承诺 |
| 高 | 大文件导入、请求总体大小、分析耗时/并发缺少充分预算约束 | 总体大小与超时限制、任务取消/资源隔离、容量测试和明确错误 |
| 高 | 自动检查刚建立，未形成强制评审和发布治理 | 分支规则、必需检查、发布签名/可回滚包、变更记录和安全响应流程 |
| 高 | Python 仅固定直接依赖，完整锁定/SBOM/持续安全扫描缺失 | 分平台锁文件、依赖更新与漏洞处理门槛、制品来源校验 |
| 中 | 异常响应先完整读入再限长度，页面提取仍克隆 DOM；只测合成页面 | 流式响应上限、复杂页面性能预算、长期离线/磁盘不足/突发崩溃验收 |
| 中 | 数据库迁移机制、完整恢复工具、长期性能和 SLO 缺失 | 版本化迁移、升级/恢复演练、数据库规模与浏览器持续运行基准 |
| 中 | 前端体积偏大，界面/可访问性验收不完整 | 按需图表模块、稳定构建链、键盘/读屏/错误恢复验收 |

普通页面正文和未识别 URL 参数仍可能含隐私。常见秘密参数清理可能合并原本不同的地址。本轮排除规则只控制后续采集，不自动抹除历史数据。损坏队列会停止处理并显示错误，但尚无可视化导出/修复向导。

## 已有优点

1. 本地数据路径、SQLite 和轻量 API 适合当前分发场景，基础记录流程不依赖大型模型。
2. 接收、展示和实验分析的边界逐步清晰，用户能区分保存事实与未验证结论。
3. 队列可靠性从隐式状态转为可测试的持久状态机，故障重试和取消有明确行为。
4. 验收开始覆盖真实扩展到数据库的链路，独立复查找到的问题被转成了回归测试。
5. 第一轮诚实展示、第二轮可信采集已经形成连贯基础；接下来应优先补安全和数据治理，而非继续增加未经验证的评分功能。

本轮可以作为可靠性改进提交，仍应标记“开发预览”。不能据此宣布达到严格企业级生产发布标准。

## 实现依据

- MV3 全局变量不可作为唯一持久状态依据，需适应 worker 生命周期：[Chrome service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。
- 将 storage.local 限于可信扩展上下文：[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。
- 内容脚本隔离环境影响 history 拦截方法：[Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。
- 使用持久隔离浏览器配置加载扩展：[Playwright Chrome extensions](https://playwright.dev/docs/chrome-extensions)。
