# 训练数据收集器：兼容既有 CSV 表头与记录分隔

## 已确认问题

分类和情感收集器均允许读取精简 CSV 文件，例如 `input,label` 或 `text,label`，
但追加时固定输出完整的六列或五列。实际合成复现中，新记录的 ID 被读成正文，
正文被读成标签，多余字段落在无列名位置，没有及时报错。

两个收集器也能读取末行没有换行的合法 JSONL，但直接追加会把两个 JSON 对象
拼在同一行，再次读取出现 `JSONDecodeError`。CSV 的最后一条记录或仅有的表头
缺少行结束符时，同样需要分隔后才能追加。

## 本次行为

- CSV 非空时保留既有表头顺序，按列名写入新记录；不改变已有字节。
- 分类收集器保留 `input` / `text` / `title` 及 `entry_id` / `id` 别名支持；
  情感收集器保留 `text` 及 `entry_id` / `id`。额外未知列的原值保留，新行留空。
- 表头必须包含支持的正文列及 `label`，且没有重复或空列名；不符合时在写入前
  使用固定错误 `CSV header is not supported` 拒绝，避免静默字段错位。
- 新文件、零字节文件及仅有 UTF-8 BOM 的 CSV 写入标准表头。
- 追加 CSV / JSONL 时，已有非空内容末字节若不是 CR 或 LF，先补换行。
  已有 CR、LF、CRLF 都保留。UTF-8 BOM 保留，不将旧文件重编码。
- JSON 数组输出、加载时的既有文本归一化与去重规则、产品界面均未改变。

上述旧字节、表头和额外列保留保证仅适用于 `append_records()`。历史加载若发现
重复或无效行，既有 `rewrite_all()` 仍会规范化重写整个文件，可能改变表头并丢弃
额外列；本批没有改变这一独立的历史清理行为。

## 验证范围

`src/lsj/tests/test_collector_append.py` 包含 147 项真实临时文件测试：

- 两种收集器，完整重排、精简、别名与额外列表头；原始文件和只有表头的文件。
- 无行尾、CR、LF、CRLF，以及有无 UTF-8 BOM；连续追加两批后仍可重载。
- 分类的三种正文别名；重复、缺少必需列及空列名在任何写入前拒绝。
- JSONL 的行尾空白；新文件、空文件、仅 BOM 文件和空追加批次。
- 逐字节确认原内容仍是输出前缀，重载后的正文、标签和条目 ID 正确；
  额外列旧值保留，新行没有字段溢出。

有效旧代码基线：123 项失败、24 项通过；格式修复后与此前 18 项恢复计数测试
联合运行：165 项通过。模块直接导入，仅实例化数据存储和合成记录；不加载模型，
不联网，不读取真实训练集或个人数据库。这些是文件存储回归，不是浏览器或真实模型验收。

## 故障边界

此处修复记录分隔和列映射，不承诺原子追加。磁盘写入中断可能留下部分新内容，
不能据此自动重放整个批次。现有文件的其他历史损坏也未全部重新校验。
读取表头、检查末字节和实际追加之间没有跨进程互斥，调用方必须保证单个写入者。
进程强制终止、掉电、`fsync` 持久化及同时外部修改文件不在本次验证范围。
收集生命周期对写失败的传播、取消和清理由独立实现与故障测试覆盖，不能仅凭
本报告的 165 项通过认定写失败处理已通过。
