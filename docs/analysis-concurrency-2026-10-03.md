# 推理期间的数据可用性与取消归属（2026-10-03）

## 确认的问题

旧 `/analyze/run_full` 在调用可选模型期间，同时持有中间件数据操作锁和 SQLite 写事务。用合成推理函数和受控线程事件复现：独立 SQLite 写事务被锁住，其他连接甚至看不到尚未提交的 running job；采集、删除和另一次图表分析均等待约 2 秒后返回 503。这是本地 API 可用性问题，与模型准确率无关。

另一个独立问题是同步 FastAPI 路由的调用方取消后，工作线程可能继续推理，而中间件已经释放模型锁。这会允许后一请求同时进入模型。仅把推理移出事务，不能解决该取消边界。

## 行为变化

- 旧 full 分成两个短写事务。第一个事务读取固定输入、处理缓存并提交 running job；关闭连接后才计算。第二个事务复核记录修订号和原任务仍为 running，再将 history 与 completed 状态一起提交。局部分析仍不覆盖全局统计。
- 两个模型入口共用单一模型锁，均不在推理期间持有数据操作锁。新采集可以完成；当前任务仍反映开始时的输入快照，下次请求会因数据集合变化而重新计算。
- 删除、恢复或直接更新记录使旧快照失效，返回 409 `analysis_snapshot_expired`，不写回旧结果。如果清空的是空库，记录修订号可能不变，但原任务已被清除；任务存在及状态检查同样阻止历史复活。
- 推理失败仍使用固定的 503/422/500 详情并保存失败任务；发布前也要检查修订号。成功结果写入失败时，savepoint 撤回局部 history，避免半成功状态。存储本身不可用时仍不能保证失败任务落盘。
- 独立回归发现旧报告含 NaN 或正负无穷时，数据库会把非法 JSON 数字保存成 completed，而当前响应序列化又可能变成 null。现在在保存成功报告的事务内拒绝非有限值，返回安全 500、保存 failed 任务且不留下成功历史，不把无效分数悄悄变成缺失值。两个分析入口也拒绝复用含非有限值的旧缓存，包括解析后溢出的 `1e999`；改为重新计算，不删除历史记录。
- 分析、导出和备份共用 `run_owned_sync`：调用方取消不会取消独立工作线程，而是等待它真正结束后才释放外层门禁；重复取消也不会提前释放。对于导出/备份，完成的孤立文件或缓冲区同时关闭。

取消 HTTP 等待不等于模型任务终止。若数据未被删除或替换，工作线程仍可能正常保存其结果；若用户同时删除或恢复数据，则发布检查会丢弃旧任务结果。前端退出后仍按既有代际规则拒绝晚响应。

## 验证范围与残留问题

新增 38 项回归全部通过（23.33 秒）。测试使用合成推理、真实 ASGI 请求、临时 SQLite 和受控线程事件，验证数据写入/删除/恢复、固定输入快照、缓存失效、空库操作、失败记录、两个入口互斥及取消后资源归属。8 个旧缓存场景覆盖两个分析入口各自的 NaN、正负无穷和 `1e999`，并检查旧历史不被删除、新结果正常复用。独立复查没有发现剩余提交阻断；完整回归和对应 CI 结果仍需单独核验。

本批不下载模型，不验证分类/情感/评分准确率。**模型仍没有硬执行期限或独立可杀掉的进程**；如果模型永不返回，模型锁和一个请求槽仍会占用，只是采集与数据管理不再被推理阶段的数据锁一同阻塞。还需要独立设计推理进程隔离、硬超时、内存预算与重启恢复。源码拆分短事务也不等于完成磁盘满、断电或所有 SQLite 锁争用验收。
