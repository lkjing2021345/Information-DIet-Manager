# Information Diet Manager 项目概览

## 一句话定位

Information Diet Manager 是一个**本地优先的信息饮食管理软件**：它在用户自己的 Windows + Chrome 环境中记录用户主动选择的网页内容，保存到本地数据库，提供记录回顾、基础统计和可选的实验性文本分析。

从技术形态看，它由 Chrome Manifest V3 扩展、本地 FastAPI 服务、SQLite 数据库、Vue 3 + ECharts 控制台和独立的分析链路组成。它已经是可本地运行的软件组合，但当前仍是开发预览，不应描述为已完成的商业产品或经过临床/心理学验证的诊断工具。

## 它解决什么问题

用户可以在本机回顾自己实际保存过的页面，了解一段时间内的内容来源和记录结构，并在需要时导入、备份、恢复或删除数据。项目把“记录事实”“展示统计”和“实验性推断”分开，避免把有限样本误写成完整浏览历史、阅读时长、心理状态或信息茧房诊断。

首要使用场景是个人信息回顾；学生/研究者可将它作为本地文本分析实验的载体；开发者可从扩展、API、数据契约和分析入口继续扩展。

## 当前可用能力

以下能力属于当前开发预览的稳定基础，具体可用性仍以对应测试和环境为准：

- 从扩展或导入文件接收页面记录，并写入每用户本地 SQLite 数据库；
- 在控制台分页查看已保存记录，区分无数据、样本不足、分析不可用和分析失败；
- 通过设置入口连接本机服务，管理本地管理密钥与扩展采集密钥；
- 对页面记录执行备份、替换恢复、单条删除和全部删除；
- 使用 Windows + Chrome 的本地启动流程运行后端、前端和扩展；
- 使用现有测试脚本对 Python 契约、扩展状态机、真实浏览器生命周期和前端构建进行分层验证。

项目保留原有科技风、玻璃卡片、动效、四图布局、主题控制和右侧抽屉。后续质量迭代只调整数据接线、验证和说明，不以重做界面为目标。

## 实验性能力与明确限制

分类、情感标签、相邻文本相似度、综合指标和完整模型推理均属于实验性链路。当前仓库包含合成输出契约和边界测试，但真实模型依赖、训练效果、跨数据集泛化、统计充分性和结论有效性尚未完成完整验收。因此，项目不会把实验结果包装成健康等级、心理状态、人格判断或诊断结论。

记录按清理后的页面地址去重，不等于访问次数、精确阅读时长或完整浏览历史。分析窗口、有效样本量、缺失指标和失败原因应随结果一起披露；缺失数据不能静默补零。备份是包含网页内容的明文 JSON，校验用于发现意外损坏，不是防篡改签名，也不保证磁盘取证级擦除。

当前正式支持边界是 Windows + Chrome + 本机运行。逐站授权、保留周期、重复访问/正文版本、多浏览器兼容矩阵、云同步和多设备协作仍属于未闭环或规划范围。

## 主要组件

```text
chrome-extension/   Chrome Manifest V3 采集扩展
src/hyh/             FastAPI、Pydantic、SQLite 与数据管理
src/backend_api/     统一后端入口
src/lsj/             实验性分类、情感、相似度与评估代码
src/analysis_engine/ 统一分析入口
frontend/            Vue 3 + Vite + ECharts 控制台
scripts/             后端、分析和依赖/仓库检查脚本
docs/               契约、质量状态、架构和路线图
```

详细数据流见 [架构说明](ARCHITECTURE.md)，当前验证和风险见 [质量状态](quality-status-2026-10-03.md)。

## 本地运行与验证

推荐先阅读根目录 [README.md](../README.md) 的 Windows + CPython 3.12 安装说明，再分别启动本地后端和 `frontend/` 开发服务器；扩展从 `chrome://extensions/` 以开发者模式加载。干净环境应使用仓库提供的哈希锁，不要使用个人浏览器配置、跟踪数据库或模型缓存作为测试输入。

常用检查包括：

```powershell
python scripts/check_repository_hygiene.py
.\.venv\Scripts\python.exe -m pytest src/hyh/tests src/lsj/tests scripts/tests -q
node --test chrome-extension/tests/*.test.cjs
npm --prefix frontend test
npm --prefix frontend run build
```

真实浏览器验收、扩展 E2E、依赖审计和模型推理需要单独的隔离环境；通过合成数据的契约测试不等于真实模型已经验收。

## 评审/作品集阅读重点

建议按以下顺序阅读：

1. 先看根 README，确认运行方式、数据口径和当前发布边界；

3. 最后看 [路线图](ROADMAP.md)，区分已完成、待验证和规划中的工作。
