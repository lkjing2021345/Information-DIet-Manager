# CI 导出就绪等待修正（2026-10-03）

## 失败与证据

提交 `30310da` 的 [GitHub Actions run 37078183809](https://github.com/luojierochester/Information-DIet-Manager/actions/runs/37078183809) 在 `test_backups_and_exports_share_two_slots_without_blocking_collection[paths1]` 失败；组合是先保持备份下载，再准备 `/export/lsj`。根代理提取的日志显示原第 110 行 `wait_for(delivery.entered.wait(), 5)` 超时，其余 697 项通过，后续浏览器步骤跳过。该次 CI 仍是失败，不能用其他本地回归结果将其描述为成功。

原测试等待正文开始最多 5 秒，产品却允许准备阶段最多 15 秒；Windows 临时导出文件在写入内容之前还必须运行实际 ACL 设置。我们在临时数据库上用 Event 暂停 ACL 调用，5 秒后旧等待抛出 TimeoutError，此时状态尚无 HTTP 响应、请求仍运行。释放 Event 后继续执行真实 Windows ACL，导出在 **6.469 秒**进入正文，返回 **200**，小于产品 15 秒预算。此时两个导出名额均占用，第三个导出返回 503，采集仍成功。

这证明旧测试会拒绝产品预算内的正常执行。CI 日志没有该次准备与 ACL 的独立耗时，不能据此断言 ACL 就是那一次超时的唯一原因。异常打印中 Event 显示 `[set]` 也不足以证明超时瞬间已就绪：测试 `finally` 会继续清理并等待请求，Event 状态可能在此期间改变。

## 仅测试改动

两个 delivery 测试文件共 8 处正文就绪等待改用共享 `wait_for_delivery_ready`：

- 等待正文事件与请求结束两者中先发生的一项。
- 从对应产品常量读取准备预算，再加 5 秒测试调度 / admission 余量；产品准备预算没有修改。
- HTTP 非 200、正文开始前请求异常 / 取消 / 提前结束均立即失败，诊断记录路径、HTTP 状态、事件状态、请求是否结束及两种预算，不输出响应正文或密钥。
- 超时时只清理测试自己的事件等待任务，不取消原请求；原测试仍负责请求清理和最终结果检查。
- 已观察到 HTTP 200 正文开始时，将后续下载结果交给原断言检查。这避免调度暂停使“正文已开始”和测试有意设置的 0.05 秒下载超时同时可见时，再产生错误的准备失败。

原有两名额限制、第三个请求拒绝、并发采集、释放后恢复、取消 / 断连、产品下载期限和文件关闭断言保留。没有修改产品源文件，也没有添加固定等待后直接假定成功的 sleep。

独立复核又确认准备取消测试的 `entered.wait(5)` 存在相同前置耗时：导出的 `_encode` 事件只有真实临时文件 / ACL 准备完成后才触发。两个文件对应的准备 Event 观察窗口也改为共用 `preparation_budgets(path)`，取消和清理断言不变。用 `_temporary_file` 前受控 5.2 秒延迟运行同一导出取消用例：旧版在 6.734 秒结束时断言失败；新版 **6.688 秒通过**，产品预算仍为 15 秒，所有临时文件关闭，请求 / 导出可用名额分别恢复为 4 / 2。该人工延迟只用于证明旧观察窗口不足，没有加入产品路径。

新增回归包括：用实际临时文件和 Windows ACL 的受控准备跨过旧 5 秒门槛；三种请求提前结束诊断；真实产品预算错误返回 503；测试自己的就绪期限到期时不取消请求。503 诊断分支使用空内存 stream 隔离其错误处理，真实文件 / ACL 验证由受控慢路径承担。

本地 Windows CPython 3.12 隔离锁定环境对最后修改完整运行两个 delivery 文件：**54 passed，29.87 秒**。独立复核另运行就绪与准备取消相关 13 项通过，并以同一 5.2 秒延迟探针确认取消场景通过。`git diff --check` 通过，仅有既有 Windows 换行转换提示。

本文件只记录测试等待合同修正；提交后的确切 GitHub CI 状态和真实浏览器结果仍需另行核验。
