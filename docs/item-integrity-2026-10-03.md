# 记录列表的存量 JSON 完整性（2026-10-03）

本轮修复 `GET /items` 对数据库 `tags`、`meta` 的读取，不修改前端设计、采集模型、存量数据库或分页顺序。

## 问题与复现

原实现对非空字段调用默认 `json.loads()`：坏语法被吞掉并替换为 `None`，非有限数能够进入成功响应；孤立 Unicode surrogate 和 300 层 JSON 则可以在响应序列化时导致 500。修复前，真实 HTTP + 临时 SQLite 红测分别观察到 `NaN` 和坏语法返回 200、孤立 surrogate 和 300 层数组返回 500，均未能准确报告存量数据异常。

## 当前合同

- 两种分页（`offset`、`cursor`）统一复用现有 `analysis_json.load_analysis_json` 的 JSON 安全规则，再通过记录列表的局部适配器返回错误。这不会将旧记录重新套入当前 `IngestItem` 模型。
- 拒绝 `NaN`、正负 `Infinity`、浮点溢出为无限值的数字、无效 JSON 语法、无法编码为 UTF-8 的文本或对象键，以及超过 64 层的 JSON 容器。字段的根对象或数组计为第 1 层；64 层仍接受。原始空字符串不是 JSON，返回错误；JSON 字符串 `""` 保持空字符串。
- 返回固定 HTTP 409：

  ```json
  {"detail":{"code":"stored_item_invalid","message":"Stored item JSON is invalid."}}
  ```

  响应包含 `Cache-Control: no-store`，不包含记录内容、原始字段、解析错误或异常 traceback。该错误与游标失效的 `items_snapshot_expired` 区分。
- SQL `NULL` 与 JSON `null` 均保持 API 的 `null`。合法对象、数组、空容器、字符串、布尔值、零、有限浮点数、大整数、中文和 emoji 保持原值；不要求旧 `tags` 必须为列表或旧 `meta` 必须为对象。
- 一个返回页内有损坏字段时，整页明确失败，不返回部分成功，也不把损坏值变成缺失值。尚未返回的后续页不会提前使当前合法页失败；实际读取损坏页时报告 409。
- 读取不会修复、删除、重新编码或覆写数据库字段，也不改变数据库修订号。错误后资源释放，授权用户仍可执行已有删除等管理操作；删除后的游标过期规则继续沿用原合同。

## 验证与剩余范围

`test_item_integrity.py` 使用真实 FastAPI 响应和临时 SQLite，包含 86 项回归：两分页、两字段的非有限数、坏语法、空原始字段、无效 UTF-8、孤立 surrogate 键/值、65/300/2,000 层输入；合法值与 64 层边界；后续页损坏、无数据改写、无敏感错误细节和错误后可写。

与既有 `test_item_pagination.py` 合计 104 项通过；验证解释器为 Windows CPython 3.12 隔离锁定环境。唯一警告来自已有 Starlette/httpx 测试客户端弃用提示。未读取个人数据库、导入真实模型或运行浏览器测试；本轮未改变前端或浏览器接口调用方式。完整后端与 GitHub CI 状态以对应提交的实际结果为准。

这是列表 JSON 的有限数、UTF-8 和深度校验，不是所有存量字段的模式校验，也不提供全库损坏自动修复。列表仍按现有方式物化一页 SQLite 数据；本轮没有增加原始行字节限制或协作读取期限，因此不将这些测试表述为大数据内存验收。过深但语法正确的历史 JSON 是本次明确收紧的返回边界。
