# 导出资源与下载隔离（2026-10-03）

本批处理普通导出和训练导出的生成内存、慢下载阻塞以及取消后的资源回收。备份/恢复仍沿用独立的版本、摘要、10,000 条和 20 MiB 合同，不把普通导出当作备份。

## 原问题与结果

原实现先 `fetchall`，再构造全部结果和完整编码字符串，`StreamingResponse` 只负责传输已经全部加载的数据。合成慢发送还证实：数据库连接已关闭，但中间件继续持有数据操作锁，另一请求等待约 2 秒后收到 503。

现在在单个只读事务内按 `ts,id` 顺序逐行取数、清理和编码，完整生成一个有上限的临时文件后关闭数据库，再发送响应。CSV 表头、列序、CRLF、原文、JSONL 无尾换行、JSON 字段语义、训练 bare 模式与过滤规则保持；JSON 对象字段输出顺序没有承诺。行数限制仍作用于过滤前的扫描行数，不能把选取最早 5,000 行变成“找到 5,000 条符合条件的训练记录”。

成功响应开始前，文件已完整生成且设置准确 `Content-Length`。传输不再持有数据操作锁，因此同时采集、删除和恢复不必等待下载结束。文件是生成时的快照：下载过程中删除记录不会改写已生成的文件，也不会把旧数据写回数据库。

## 固定资源边界

| 范围 | 当前边界 |
| --- | --- |
| 扫描条数 | 请求默认 5,000，最多 200,000，仍受下面其他预算约束 |
| 最终文件 | 最多 64 MiB UTF-8 字节，包含包装、分隔符和 CSV 表头 |
| 单条源记录 | SQLite 先计算所有导出字段的合计字节数，超过 128 KiB 时不将整行读入 Python |
| 训练去重 | 保留精确规范化字符串；按字符串实际 Python 对象大小加每键 128 字节保守开销，最多 32 MiB 预算；重复键不重复计费 |
| 同时导出 | 最多 2 个，包含生成和传输；第三个立即 503，留出普通请求容量 |
| 生成时间 | 15 秒协作式期限，逐行/编码检查并设置 SQLite progress handler；不是对阻塞磁盘或系统调用的硬实时中断 |
| 下载时间 | 开始发送后最多 30 秒；每块至多 64 KiB |

输出、源行或去重预算超限返回 413，数据库忙或生成超时返回 503；临时存储不可用返回 507，无法编码的旧记录返回 409。错误在成功响应开始之前返回，不截断后伪装成功，也不回显页面文字、能力密钥或临时路径。发送开始后的断连/超时会中止传输，客户端应以 Content-Length 检查完整性；此时不能再改发 JSON 错误响应。

临时文件创建后，Windows 在写入任何浏览内容之前设置仅当前用户和 SYSTEM 的 ACL；采用关闭时删除的文件句柄。正常完成、`http.disconnect`、发送异常、超时和取消都显式关闭。生成阶段取消时，调用方继续持有容量和数据操作锁，等待有期限的工作线程退出；如果线程已经产出文件则立即关闭，绝不发送孤立响应。这样取消请求不能绕开同时导出上限。关闭时重复报告的磁盘错误不会覆盖原 HTTP 错误或取消信号。实现依据 [Python 3.12 tempfile 文档](https://docs.python.org/3.12/library/tempfile.html)；文件删除不等同于底层存储的安全擦除。

## 证据与限制

原有 17 项导出合同测试通过；新增 31 项资源边界测试覆盖精确字节上限与超限、Unicode、训练顺序/过滤/去重、旧记录大字段、磁盘故障及双重关闭故障、SQLite 扫描超时和后续可写性。27 项独立 ASGI 测试控制真实应用的响应发送，检查慢消费者、并发容量、生成/传输取消以及文件和锁回收，包括 ASGI 2.3 的 disconnect 事件和 2.4 的 send 异常。完整 Python 回归（后端与工程脚本）386 项通过，另有 26 个 unittest subtest；扩展单元 38 项、扩展真实浏览器 10 场景通过。保留一条既有 Starlette/httpx 弃用提示；最终 CI 需对应推送提交核验。

独立合成 SQLite 测量使用每行 990 个中文字和约 7,000 字符 ASCII 元数据，在响应未消费、没有 TestClient 缓冲的条件下记录生成阶段：

| 行数 | 输出字节 | 生成秒数 | Python 分配峰值 MiB |
| --- | ---: | ---: | ---: |
| 1,000 | 13,172,562 | 1.443 | 0.114 |
| 4,000 | 52,703,562 | 1.231 | 0.095 |

这些是本机单次 `tracemalloc` 结果，不能代表进程 RSS、文件系统缓存、机器间性能或完整 200,000 行压力验收。旧实现同类 1,000 行负载的记录约为 69.72 MiB Python 分配峰值，见[之前的测量](export-contract-2026-10-03.md)。新实现去除了随完整输出增长的 Python 列表和字符串副本，但不能据此声称整个进程只有 0.1 MiB 内存。

仍待验收：长期负载、实际磁盘满/断电/强制终止演练、进程 RSS 与不同存储性能。系统调用阻塞可能超出协作式生成期限；导出已完成的快照仍可能包含后来删除的记录。本批结束时备份接口仍沿用原有数据操作锁策略；后续已在[独立备份批次](bounded-backup-2026-10-03.md)处理慢发送、并发预算和取消归属。真实模型效果、许可证和发布治理也不属于本批完成范围。
