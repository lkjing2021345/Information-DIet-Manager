## 旧工作区更新前的注意事项

`git rm --cached` 只移除索引项，保留执行该命令的工作区文件。因此，本次维护工作区中的旧库与根依赖目录保留在本地，并由忽略规则保护。

这不意味着其他旧克隆执行 `git pull` 时也会自动保留原先跟踪的文件：Git 可能删除与旧提交一致的工作区文件。已有用户应在更新前退出服务，将自己的旧库另行备份到不受 Git 管理的私有目录；若仍使用旧库路径，继续明确设置 `IDM_DB_PATH`，或通过已支持的备份/恢复功能迁移数据。不要把 `.gitignore` 当作备份机制。

本轮不重写 Git 历史。旧提交仍可能包含原先跟踪的数据库；从当前树取消跟踪不能撤回历史副本，也不能证明文件中从未存在敏感内容。历史数据审查与历史重写需要单独确定范围。

## 索引门禁

在仓库根目录运行：

```text
python scripts/check_repository_hygiene.py
python -m pytest scripts/tests -q
```

检查器只使用 Python 标准库和 Git。它通过 `git ls-files --cached -z` 检查当前索引路径，不遍历本地用户数据，不打开数据库、密钥或模型内容，也不会修改或删除文件。NUL 分隔保留含空格和中文的路径；规则忽略大小写，防止 Windows 路径大小写绕过。

拒绝范围包括：

- 任意层级的 `node_modules`、虚拟环境、缓存、构建输出、测试报告和日志目录。
- SQLite 数据库及 WAL、SHM、journal、锁文件。
- 环境配置和凭据文件。只允许文件名恰为 `.env.example` 的模板；`foo.env.dataexample` 或 `.env.production.example` 不属于例外。
- 常见模型权重文件、项目模型下载目录、检查点和本地训练数据目录。
- 根 `package.json`、`package-lock.json`、`npm-shrinkwrap.json`，防止重新引入未纳入既定安装/审计流程的根 npm 入口。

退出码为 0 表示索引路径符合规则，1 表示发现禁止路径，2 表示不能读取 Git 索引。Git 缺失、非仓库路径或读取失败不会被报告为通过。即便有人使用 `git add -f` 绕过 `.gitignore`，索引检查仍会发现该路径。

`.gitignore` 是减少误操作的第一层；CI 中的索引检查是第二层。未来若要增加新的根依赖管理方式或提交某类制品，应先明确其安装、安全审计和发布流程，再审查规则变更，而不是直接强制加入。

## 测试证据与限制

12 项标准库测试使用真实临时 Git 仓库和合成文件，验证源码/模板放行、强制加入已忽略文件仍被拒绝、数据库伴生文件、模型与缓存、旧根清单、大小写/中文/空格路径、缺少 Git 和非仓库失败，以及 `git rm --cached` 后本地文件仍存在且索引检查通过。测试不使用个人数据库、浏览器资料或真实密钥；也可直接通过 `python -m unittest discover -s scripts/tests -p test_repository_hygiene.py -v` 运行。

另从本轮暂存索引导出全新源码副本，确认不含根依赖目录、根 npm 清单或旧数据库；为副本新建 Python 3.12 虚拟环境，并分别在两个 npm 子项目执行 `npm ci`。结果如下：

- 索引门禁检查 100 个源码路径通过，`pip check` 通过。
- 后端与仓库门禁测试合计 223 项通过；前端单元测试 35 项通过。
- 生产构建后的页面真实浏览器场景 25 项通过；扩展真实浏览器场景 10 项通过。使用独立 Chromium 和合成数据，不使用个人浏览器配置。
- 保留原界面结构、主题控制和抽屉的浏览器断言通过；构建仍有主包超过 500 kB 的提示，后端仍有 1 条 Starlette/httpx 弃用警告。

该副本验证的是本轮源码取消跟踪后的可运行性；真实模型推理和正式安装包仍未验收。此时 Python 输入文件尚未完成全依赖哈希锁定，相关补强另行记录。

路径门禁不能识别任意 JSON、CSV、源码或文档内嵌的秘密和浏览记录，不能代替秘密扫描、数据授权审查或人工评审。允许合成文本 fixture 不代表允许提交真实用户数据。历史提交、外部下载模型、第三方许可证及正式发行制品审计也不在该检查范围内。

制作发布包时应使用审查后的提交文件清单，避免直接压缩含本地数据库、依赖和缓存的整个工作目录。本轮不选择项目许可证，也不构成正式企业级发布验收。
