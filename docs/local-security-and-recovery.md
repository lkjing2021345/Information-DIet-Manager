# 本机访问与数据恢复边界

适用版本：第三轮改进，Windows + Chrome、每位用户独立本机运行。它不是共享在线服务的账户/租户权限系统。

## 数据流与权限

```text
网页 → 扩展受限存储/待确认队列
              ↓ collector_token，仅提交记录
       127.0.0.1 上的 FastAPI
              ↓ SQLite 事务
       当前 Windows 用户的数据目录
              ↑ admin_token，查询/分析/数据管理
       本机 Vue 界面（管理密钥仅存页面内存）
```

每次请求先检查实际对端为回环 IP、Host 为回环主机、Origin 在允许列表中，再检查 Bearer 密钥和权限。HTTP 来源由协议、主机和端口共同决定，不能把不同端口视为同一来源：[FastAPI CORS 文档](https://fastapi.tiangolo.com/tutorial/cors/)。没有 Origin 的本机命令行请求仍需密钥。

管理密钥允许查询、导出、分析和删除所有本地数据；采集密钥只允许 `/collect` 与自身 `/session`。从泄露的采集密钥不能直接升级到读取权限，但持有它的本机调用者仍可提交错误或伪造记录。密钥是权限凭证，不是网页真实性证明。

两把密钥各由 `secrets.token_urlsafe(32)` 生成，并以常量时间比较检查：[Python secrets 文档](https://docs.python.org/3.12/library/secrets.html)。Windows 先给临时文件设置仅当前用户及 SYSTEM 的显式 ACL，再写入密钥、刷新到磁盘并替换正式文件；启动还会重新检查/应用权限。权限设置失败或密钥文件损坏时停止启动，不静默取消认证或换掉密钥。密钥字段不出现在配置对象的 repr 中。

扩展将采集密钥持久化在仅可信扩展上下文可访问的 storage.local；这不是加密密钥库。不要把管理密钥填入扩展。界面在断开、刷新或收到 401 后忘记管理密钥；取消在途请求并拒绝旧会话结果。服务重启沿用同一文件，密钥轮换需要停止服务后显式执行脚本。

## 防御范围与已知限制

| 情况 | 当前行为/边界 |
| --- | --- |
| 未授权网页访问本机 API | 来源、Host、回环对端和密钥检查；无 Cookie 鉴权 |
| 仅持有采集密钥尝试读取或删除 | 拒绝访问；有回归测试 |
| 意外暴露监听地址、伪造 Host | 推荐启动器只监听回环且禁用代理头信任；应用再次校验实际来源 |
| 超大请求、慢请求、操作竞争 | 限制字节、读取总时限与进入数量；串行数据操作，忙时返回可重试 503 |
| 同一数据库启动多个 API 进程 | 操作系统文件锁拒绝第二个进程，服务退出时释放 |
| 相同 Windows 用户权限的恶意软件、管理员、被控制的浏览器/系统 | 不在当前防御保证内；可以读进程/剪贴板/用户文件，不能靠本机 Bearer 消除 |
| 数据在磁盘、同步盘或下载备份中泄露 | SQLite 和备份没有应用层加密；使用私有用户目录和可信备份位置 |
| 恶意依赖、扩展供应链、漏洞持续检测 | 尚无完整 SBOM、供应链门槛或独立安全审计 |
| 高负载或长期分析占用 | 单机串行设计会延后采集，扩展保留并重试；模型 CPU/内存隔离和硬超时尚缺 |

不能把这些边界解释为“顶级企业认证”或“零漏洞”。CORS 本身也不能替代认证。前端页面及本机服务需来自可信代码和依赖；不要经公网反向代理暴露服务。

## 删除与恢复语义

备份仅包含页面字段，不包含密钥、扩展队列、原记录 ID、创建时间、向量或分析缓存。下载上限为 10,000 条和 20 MiB，不支持超限部分导出。历史记录不符合当前契约时拒绝导出，原数据保持不变。SHA-256 是损坏检测，不能鉴别来源或抵御主动篡改。

恢复是全量替换，空备份也会清空数据；界面明确确认后发送专用确认头。先完成格式、版本、字段和校验和检查，再在一个 SQLite 事务中删除旧记录、插入全部记录、重建向量、清空分析。归一化后的重复 URL 或中途存储错误会回滚整个事务。故障注入测试验证了第二条向量写入失败后五张表全部保留原状；不等价于已经完成真实断电、磁盘控制器故障或损坏磁盘恢复实验。

删除单条会同时删除其向量，并清空所有依赖原数据的分析表；删除全部也在一个事务中完成。API 操作串行化，避免已开始的旧分析在成功删除后写回旧快照。直接写 SQLite 的外部工具不受该 API 锁保护。

操作前先暂停扩展，再清空待同步队列。服务端已经接收的请求无法从扩展撤回，之后继续浏览同一网页仍可能再次采集。删除数据库记录不会删除另存的 JSON、浏览器缓存、系统备份或磁盘快照；启用 SQLite secure_delete 也不构成取证级擦除承诺。客户端断开或超时后，服务端可能已提交，应先刷新核对。

## 升级与排障

1. 默认数据库从仓库内移动为用户目录路径，但**不自动搬迁旧文件**。空列表时先核对服务启动所用 `IDM_DB_PATH`；不要删除旧库。迁移步骤见根 README。
2. 401：核对密钥是否完整，以及是否从当前数据库旁的文件复制；轮换后需重连。403：核对角色、Host 和前端 Origin。
3. 503：服务正在处理其他请求，按 Retry-After 等待；不要连续启动多个进程或重复点击恢复。
4. 第二进程被拒绝：先停止对应服务。锁文件可以保留，其是否存在不代表锁仍被持有，不要把删除锁文件作为恢复方法。
5. 密钥文件损坏：停止服务，保留原文件用于本机排查，使用 `scripts/rotate_local_keys.py` 生成新凭证；勿把文件或凭证内容附到 GitHub issue。
6. 409/413 导出失败：当前记录不兼容或超出容量；先离线备份数据库原文件，后续采用经过验证的迁移工具，不应手改备份校验绕过错误。

完整接口与错误约定见 [API 契约](../src/hyh/CONTRACT.md)，验收结果见 [第三轮记录](round-3-improvements.md)。
