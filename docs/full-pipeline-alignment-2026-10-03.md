# 完整评分在发布前校验模型输出的记录归属

日期：2026-10-03。本批修复 `/analyze/run_full` 的推理输出边界，不修改评分公式、模型、阈值或产品前端。

## 已确认的问题与证据边界

可视化路径原已要求推理输出与输入的行数、ID 顺序和时间戳顺序相同；完整评分路径直接调用评分器，并使用 `execution.input_count` 发布总数。若适配器输出丢行、乱序、重复 ID 或改变时间戳，完整评分仍可能完成并保存不属于原窗口序列的结果。

用真实应用 API、临时 SQLite、合成推理结果和评分器替身运行六组探针：四组异常输出均返回 HTTP 200、`completed`，调用两次评分入口，并保存成功任务、报告和一条分析历史。同样输出在可视化路径均为 `failed`。丢行组尤其出现窗口/渠道计数为 6、总数/分类计数为 5 的矛盾。正常输出和仅改变 DataFrame index 的两组对照均成功。

这证明的是缺少输出契约校验，并非真实模型曾经丢行或错位。当前分类、情感和相似度批处理源码均保留输入行，给原序列的副本添加结果列；空文本或无效测量也保留行。评分器内部在副本上做的过滤和时间排序属于已声明的旧评分预处理，本批没有改变该行为。未加载模型权重、读取个人数据库或访问外部模型服务。

## 改动

`_run_lsj_pipeline()` 在两个评分入口之前验证：

- `execution.input_count` 必须是严格的 Python `int`，且等于原输入数；布尔值、字符串、浮点数、缺字段等不再通过隐式整数转换。
- 输出行数、`id` 列序列、`ts` 列序列必须与输入一致。
- 缺列、坏结构及检查期间的普通异常统一变为固定内部错误，通过既有失败处理返回安全 HTTP 500。它们不会被当成缺少测量的 HTTP 422，也不会调用评分器。

正常聚合返回原输入的可信行数。校验不要求 DataFrame 使用默认 index，不增加对合法指标值的限制。空输入依旧直接返回空结果，不初始化推理。

## 回归

新增 `src/hyh/tests/test_full_pipeline_alignment.py`：19 组无效输出、2 组合法输出和 1 组空输入，共 22 项。旧产品代码上为 **19 failed / 3 passed，5.00 秒**。坏结构有些原本会在稍后失败，但旧实现已经调用评分器，因此也不满足新增的评分前拒绝断言。

异常测试检查固定安全响应、评分器零调用、失败任务无结果、无成功历史/全局统计、页面数据不变，以及修复适配器后的请求可以重新计算且不是失败缓存命中。合成私密异常标记不会进入响应、任务详情或测试捕获的日志。成功测试保留真实聚合与非默认 index 的兼容性；评分本身是替身，不能据此验证模型或评分准确性。

修复后专用 22 项与既有旧评分统计 49 项联合为 **71 passed / 1 条既有 Starlette 警告，13.68 秒**。无需修改旧测试输入或断言；主流程将在各项修改冻结后统一运行最终集成检查。

旧行为探针及回归原始日志仅保存在 ignored 的 `output/playwright/quality-20261003/full-alignment-review/`。全套回归、独立复查、真实浏览器和精确提交 CI 由主流程另行记录，不由本项局部测试代替。
