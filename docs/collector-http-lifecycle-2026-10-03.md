# 训练收集器 HTTP 生命周期修复

两个工具此前在同步 `BaseModelClient.__init__()` 中创建 HTTP 客户端。模型池第二项 provider 不支持、第二个客户端包装器构造失败，或后续 `DataStore` / `ProgressTracker` 构造失败时，收集器尚未进入 `collect()` 的异步清理边界，已经创建的 HTTP 对象无法由该边界关闭。合成客户端用临时文件句柄证明了清理调用缺失；这不等于已证明真实 HTTPX 在首次请求前泄漏网络连接。

现在同步构造只保存配置、限流参数和锁，不分配 HTTP。OpenAI、Anthropic 和继承 OpenAI 的 local 客户端在异步生成的首次请求前创建并立即保存 HTTP 引用；检查、创建与赋值之间没有 `await`，同一事件循环内的并发首次请求共享一个实例。分类工具的 response_format 回退和现有重试继续复用该实例。

`close()` 先禁止后续生成；未使用过的客户端无需创建资源即可关闭。底层 `aclose()` 正常返回后清除 HTTP 引用，重复关闭不会重新分配资源。首次关闭抛异常或被取消时，向上传播错误并保留引用，不重新开放生成。调用方可以再次调用 `close()`，但实际能否继续清理取决于底层实现，不能将再次正常返回解释为资源已经释放。模型池遍历全部客户端并保留首次关闭错误、收集器取消及 finally 清理的既有逻辑不变，没有嵌套事件循环或后台清理任务。

## 验证

新增 `src/lsj/tests/test_collector_http_lifecycle.py`，使用真实池、客户端生成方法及收集器清理逻辑，HTTP 由仅持有临时文件句柄的替身代替。未联网、读取个人配置或浏览数据库、加载真实模型。取消收集测试替换派发方法，让真实池生成请求停在替身 HTTP 的等待点；它不是新的完整调度器验收。

- 首批 31 项对旧源码实测为 **28 failed / 3 passed，1.50 秒**；修复后 **31 passed，0.65 秒**。通过的旧版对照为分类 response_format 回退及双工具普通网络重试。
- 随后补充双工具在 `aclose()` 等待期间真实 `task.cancel()` 的测试，并加强成功关闭后不得重开的断言，最终本文件为 33 项。
- 最终与并发配置、持久化故障、日志隐私、恢复计数及停止边界测试联动为 **153 passed，9.73 秒**。`git diff --check` 通过。
- 独立复核另外通过这 33 项，并使用锁定的真实 HTTPX 客户端与本机 `127.0.0.1` 固定合成响应完成 4 组检查，覆盖两个工具的 OpenAI/local 首次使用、复用、正常关闭不重开及限流等待期间关闭。它不是远程模型推理验收。完整回归及精确提交 CI 由总验收另记。

覆盖构造中途失败及后续组件失败时零 HTTP 分配、三种 provider 正常请求参数和响应、首次并发分配、回退及重试、HTTP 构造异常延迟至有归属的生成阶段、请求取消后的收集器清理、未使用即关闭、关闭异常与取消后保留引用、可重试替身再次清理、防止重开，以及多个客户端关闭时的首次错误保留。替身支持关闭失败后的重试，不代表真实 HTTPX 具备同样的失败恢复行为。

## 兼容与保证边界

`ModelPool`、collector 的同步构造接口及 CLI 不变。`client.http` 在首次生成前和底层 `aclose()` 正常返回后为 `None`；仓库内没有依赖提前访问它的调用。HTTP 构造错误会从构造阶段延迟到首次生成，并遵循现有重试策略；不改变请求参数、重试次数、正常响应和限流策略。

独立异常探针使用 HTTPX 0.28.1 和合成 `AsyncBaseTransport`：第一次底层关闭抛出 OSError 后，HTTPX 已为 `is_closed=True`；再次 `aclose()` 直接返回，底层关闭调用仍只有 1 次、合成资源尚未释放，而包装器会清除引用。证据保存在忽略的 `output/playwright/quality-20261003/collector-http-close-boundary.json`。因此真实 HTTPX 异常关闭及关闭期间取消后的完整释放仍是剩余验收边界，本批没有修复或保证其失败恢复，也没有调用依赖私有 API 绕过它。

本批保证项目自身的同步客户端构造不分配 HTTP，成功返回的 HTTP 对象立即具有可调用关闭的归属；正常关闭路径经合成回归和真实 HTTPX 本机检查验证。第三方构造器内部先分配再抛错、却不返回对象时的自清理仍由该依赖负责；可选模型资源、多线程/多事件循环共享客户端、反复取消和强杀下的清理完成不在保证范围内。直接使用客户端或池的调用方仍须等待关闭；本批没有增加自动重试关闭策略或声称真实远程模型验收。
