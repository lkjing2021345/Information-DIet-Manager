# 密钥轮换 CLI 参数边界（2026-10-03）

`scripts/rotate_local_keys.py` 原先不解析命令行参数，`--help`、`-h` 或拼错的参数都直接进入真实轮换。用户只是查看帮助，也会改变管理和采集两把密钥；下次启动服务后旧密钥失效。这是 CLI 误操作缺陷，不是未授权的远程访问或密钥泄漏。

真实 Windows 脚本探针仅使用自建临时路径：无参数先生成合成凭据，再执行 `--help` 和未知参数。旧脚本两次均返回 0、打印轮换成功、实际改变两把密钥，没有输出帮助；凭据值未出现在输出中。没有启动服务、创建浏览数据库、访问个人配置或运行模型。

脚本现在先用标准库 `argparse` 处理参数，再导入数据库配置和安全模块：

- `--help` / `-h` 返回 0，只显示帮助。
- 未知选项或多余位置参数返回 2，不轮换密钥。
- 上述路径不读取产品数据库配置、不获取进程锁、不创建目录或凭据；即使 `IDM_DB_PATH` 为空、空白、已有目录，或设置了无效环境密钥，也不影响帮助 / 参数错误处理。`python -S` 禁用 site packages 时仍可处理这些参数。
- 无参数继续执行原有轮换，不增加确认提示或新轮换策略。配置环境密钥、其他进程持有数据库锁时仍拒绝；正常轮换不改数据库。

专用回归使用真实子进程、自有临时路径、合成凭据与真实 Windows ACL；子进程使用 `CREATE_NO_WINDOW`。对已有凭据逐字节核对，另验证新目录不创建、正常轮换改变两把密钥而数据库字节不变、输出不含凭据、锁和环境密钥限制保持。

最初的 6 项夹具在旧实现下报告 12 个参数行为失败和 1 个夹具清理失败：正常轮换的合成 SQLite 连接只提交但未关闭，导致 Windows 清理报 WinError 32。已明确关闭该连接并清理两处自建残留，不将这一失败算作产品缺陷。为避免回退共享源码，最终 7 项夹具另对当前提交的旧脚本字节在 ignored 副本中运行：**7 项方法、14 个参数 subtest 断言失败、0 个错误**；正常轮换和锁 / 环境限制对照通过。修复后专用回归为 **7 passed、14 subtests passed**。

这次没有修改前端、业务 API、密钥格式、私有 ACL、数据库路径或轮换时序。无参数配置错误仍使用既有错误行为；本批不扩展为损坏文件自动修复、异常断电恢复或完整 CLI 错误格式重构。脚本联动、独立复核及精确提交 CI 结果由本轮验收记录另行列出。
