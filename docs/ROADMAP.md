# Information Diet Manager 路线图

本文把未来工作写成可核验的阶段目标。状态含义为：**已实现**表示仓库已有代码或文档证据；**待验证**表示存在实现或测试入口但尚未完成规定验收；**规划**表示尚未承诺实现。时间从当前开发预览继续迭代起算，不代表发布日期承诺。

## 路线原则

1. 先建立可信的 Windows + Chrome 本地开发预览，再扩大分析能力；
2. 稳定基础、实验性分析和长期愿景分开写、分开验收；
3. 每个里程碑都要同时记录功能证据、测试证据、数据/隐私边界和剩余风险；
4. 保留现有前端视觉设计，只在必要时修改数据接线、错误语义或验证入口；
5. 不把合成数据测试、静态构建通过或演示效果写成真实模型有效性证明。

## 0–3 个月：可信开发预览

**目标**：让首次使用者、评审者和维护者能清楚知道软件能做什么、如何验证、哪里仍不可靠。

### 工作项

- 完成 README、项目概览、架构和路线图之间的交叉链接与术语统一；
- 固化“稳定基础 / 实验性分析 / 未支持范围”清单；
- 复核数据删除、备份/恢复、密钥轮换、缺失数据和失败状态的用户可见语义；
- 完成 Windows + Chrome 的隔离运行说明、依赖锁和验证命令复查；
- 建立发布前检查清单：Python 契约、扩展单测/E2E、前端单测/构建/E2E、仓库卫生和依赖审计；
- 追踪真实模型入口的依赖、日志、超时、进程隔离和失败回收问题，但不提前宣称模型结论有效。

### 验收门槛

- 新用户可按 README 在干净环境启动本地后端、前端和扩展；
- 稳定基础路径有对应自动化测试，删除/恢复不会把旧分析结果写回；
- 备份包含版本与完整性校验，失败恢复保持事务边界；
- 真实浏览器检查使用临时数据库和合成密钥，不使用个人浏览器配置；
- 每项未完成能力在文档中标为“待验证”或“规划”，不存在把合成模型输出当作真实效果的表述。

## 3–6 个月：可审查的实验分析

**目标**：在不改变本地优先产品边界的前提下，让实验分析具备可重复、可解释、可回退的验证基础。

### 工作项

- 为分类、情感、相似度和综合指标分别定义输入范围、有效样本量、缺失值、失败状态和输出版本；
- 使用固定的合成夹具和独立人工标注/基准数据，报告准确率、召回率、F1 或其他适用指标及置信区间；
- 明确模型与数据版本、随机种子、运行资源、超时和取消行为，隔离模型进程与用户服务；
- 在真实浏览器和本地临时数据库中验证分析触发、缓存失效、删除/恢复后的结果一致性；
- 评估分析耗时、内存、并发上限和大数据集失败方式；
- 在界面保持原设计的前提下，继续维护“不可用 / 样本不足 / 失败 / 缺失指标”的明确语义。

### 验收门槛

- 每个公开分析指标都有数据口径、基线比较、验证数据来源和已知失效条件；
- 真实模型验收与合成契约测试分开记录，可在干净环境复现；
- 取消、超时、模型崩溃和依赖缺失不会伪装成成功结果；
- 任何涉及心理或健康解释的表述仍被明确禁止，除非未来另有严格外部证据和产品决策。

## 6–12 个月：受控的平台扩展

**前提**：前两个阶段的可信度和实验分析门槛已通过评审。若没有通过，继续修复本地版本，不自动进入平台化。

### 候选工作项

- 逐站授权、敏感站点策略和可配置保留周期；
- 重复访问、正文版本和历史快照模型；
- 其他浏览器或系统的兼容性评估，先建立矩阵再承诺支持；
- 可选的跨设备/云同步设计，先完成威胁模型、密钥管理、删除传播和迁移方案；
- 面向协作者的 API 契约、贡献指南、问题模板和版本发布流程。

### 验收门槛

- 新平台或云能力有独立隐私评审、迁移/删除测试和失败回滚方案；
- 在没有兼容矩阵、备份迁移和权限边界证据前，不把候选能力写成正式支持；
- 发布产物、依赖、许可证、变更记录和安全边界可追溯；
- 继续保留 Windows + Chrome 本地模式作为可用回退路径。

## 当前不承诺的事项

本路线图不承诺诊断、健康评分、人格分析、完整浏览历史还原、精确阅读时长、自动化内容处方、默认云端存储或多人协作。它们即使出现在实验代码、历史文档或未来讨论中，也必须经过单独的产品、数据和验证决策。

## 里程碑记录模板

每次完成一项路线图工作，记录以下内容：

- 实际提交或变更范围；
- 功能和数据契约；
- 自动化测试、真实浏览器检查和 CI 结果；
- 使用的合成数据、临时数据库和模型环境；
- 尚未验证的假设、已知风险和下一步；
- 是否影响原有前端视觉设计（默认应为“不影响”）。
