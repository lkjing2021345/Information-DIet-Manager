# 分类训练数据置信度完整性修复

## 已确认问题

分类合成数据工具原先将无法转换的模型置信度回退为 `1.0`，并将越界数值截到 `[0, 1]`。在 Python 的原有 `min` / `max` 调用顺序下，NaN 也会变成 `1.0`。复核路径对 NaN 的“小于门槛”比较为假，因此同标签的坏响应可能通过复核。

离线探针用 `min_confidence=0.9` 和真实生成后处理、质量过滤、去重、写入及进度保存，确认显式 `null`、坏字符串、`NaN`、正无穷、`1.2`、`true` 六组响应均能写成置信度 `1.0`。历史 JSON、JSONL、CSV 也接受非有限数或越界值；真实恢复流程将此类记录计为已完成，而不发起生成。探针没有访问模型、网络或个人数据库，不能据此判断既有真实训练集是否已经受影响。

## 修改与兼容边界

- 分类生成、复核、历史读取和 `min_confidence` 配置共用有限 `[0, 1]` 数值检查。显式布尔值、空值、坏类型、无法转换的字符串、溢出数值、NaN、无穷及范围外数值均无效，不再回退或截成高置信度。
- 生成遇坏值按生成失败处理，复核遇坏值拒绝候选。有效值仍使用原最低置信度和 `max(0.7, min_confidence)` 复核门槛；没有提高默认门槛或重新设定产品筛选政策。
- 历史文件只要含显式非法置信度，就抛固定安全异常、停止初始化。检查覆盖重复 ID 行，不能通过去重隐藏坏值；不能把坏值计为完成，也不能先剔除再重写原文件。输出文件字节保留，失败状态可以写入独立进度文件，模型池仍按既有生命周期关闭。用户需另行检查和修复历史文件，本次不自动修复。
- 合法数字字符串继续兼容 JSON、JSONL 和 CSV。**缺字段仍默认 `1.0`，这是暂保的旧格式兼容值，不是测量结果或经过校准的置信度。** 同样不按新的运行门槛回删历史上合法的低置信度记录。
- `min_confidence` 在日志、模型池等初始化副作用之前验证。非法配置立即失败；原来会静默截断的范围外配置也被明确拒绝，合法值及默认 `0.0` 保持原义。
- 新失败日志只有固定事件和阶段，不含原响应、原始坏值、正文或异常文本；坏置信度不再流入日志里的非标准 NaN/Infinity 数值。

情感采集工具没有置信度字段或门槛，本次没有为它增加该政策，也没有修改它。前端、正式采集、分析模型和训练参数均不在本次修改范围。

## 本地回归证据

专用回归首先在旧实现运行，得到 **99 failed / 34 passed，3.90 秒**，保留了对合法格式的对照。实现修复后，专用回归与原隐私、恢复回归先得到 **174 passed，3.99 秒**。

最终专用文件增加九项成功生成、复核、持久化往返对照，共 **142 项**。覆盖内容包括：

- 17 类显式坏值经过真实 `_process_spec`，不进入输出文件、不增加确认写入计数；生成与复核保留各自失败计数。
- JSON、JSONL、CSV 的非法历史阻断，逐字验证原文件不变、零模型调用、池关闭；重复 ID 不能掩盖坏置信度。
- 缺字段、有限数值、数字字符串及合法低值历史继续恢复；不根据当前较高门槛重筛历史。
- 配置失败发生于日志和客户端构造之前；日志不含合成敏感标记，且可按严格 JSON 解析。

连同既有隐私、恢复、追加格式、持久化故障、停止边界、HTTP 客户端生命周期和并发配置回归，最终局部联合验证为 **442 passed，14.82 秒**。

冻结后独立复核专用 142 项通过（2.62 秒）。复核确认历史校验早于去重与重写、专门异常不会被普通无效行处理吞掉，且新配置校验早于日志及模型池初始化。该保证针对生成、复核和恢复入口，不涵盖外部调用者手工构造 `Record` 后绕过入口直接写文件。

这些是锁定测试环境中的本地合成数据回归，没有调用真实生成模型。整套后端、浏览器、提交及精确 SHA 的 CI 验收由集成流程另行记录；本次不证明模型置信度经过校准，也不证明合成训练样本的标签正确率。
