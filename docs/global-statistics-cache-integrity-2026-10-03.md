# 轻量全库统计缓存的复用边界

日期：2026-10-03。本批处理 `/analyze/run` 与 `/dashboard/summary` 共用的轻量统计缓存，不修改统计公式、模型、前端、完整分析或图表分析路径。

## 已确认的问题

原 `_global_statistics()` 只检查缓存的范围、版本、数据版本和总数；有限 JSON 只要这四个值匹配，就会直接返回并写入当天 `stats_daily`。删除必需字段可能导致正常请求返回 500；其余结构完整但值不符合轻量统计合同的缓存，则可能被当成当前结果。

临时 SQLite 与真实 API 的十二组探针（两个入口各六组）证明：

- 四条正常合成记录，覆盖时间戳 0、UTC 跨日和最大允许值，以及大小写渠道、未知/空/缺失渠道，正确得到总数 4、学习 1、其他 3、重复率 0.5。
- 保持四个缓存标记不变，单独更改渠道为 `edu=999, other=-1`，返回 200 / cached，并把坏渠道写入 daily；删除渠道字段则返回 500，未重算。
- 把轻量统计原应为 `None` 的情感值改成数值，接口仍成功返回；真实缺少全部内容 hash 时，把重复率 `None` 改为 0 也被接受。
- 把 payload 的日期改为 1970，仍成功作为当前缓存返回。`/analyze/run` 还把这些有限但无效的 payload 复制为新的历史记录。

这是已存缓存不完整或不一致的处理缺陷，不代表普通采集必然产生上述损坏。合法输入、旧 daily 投影隔离、数据修订和正常缓存命中已有测试，本批没有将它们重复报成新问题。

## 实现

新增 `src/hyh/global_statistics_contract.py`，`app.py` 仅增加导入并替换轻量缓存复用谓词。仍先执行原有有限数、深度和 Unicode JSON 检查，再校验当前版本 1 的必要外层字段：

- 当前 UTC 日期、数据版本和总数一致；版本、计数、时间戳使用严格整数，不把布尔值当作 0/1。
- 渠道必须是原来的五个键，值为非负整数，总和等于总数。
- hash 样本数介于 0 与总数之间；没有样本时重复率必须为 `None`。有样本时比例在 0 到 `(样本数−1)/样本数` 之间，因为至少存在一个不同的非空 hash；单样本只能为 0。
- 保留原重复度指标名称，情感比例及平均极性必须显式为 `None`；生成时间是合法毫秒，`cached` 是布尔值，向量回填数是总数以内的非负整数。

无效缓存回到原 SQL 计算路径，保留旧历史行，再按原流程写入当前 projection 和新记录。合法缓存保留原生成时间；summary 命中不反复增加历史，`/analyze/run` 仍记录本次运行，`force=true` 仍绕过缓存。没有修改事务、数据库字段、备份、模型或展示设计；没有新增推理依赖。

## 定向回归

新增 `src/hyh/tests/test_global_statistics_cache_integrity.py` 共 33 项：23 个代表性的字段/计数/缺失语义损坏，两个入口各一项缺 hash 不能伪装零，两个入口各一项回填后失败的事务回滚，以及空库、单条、全缺/部分缺 hash、合法零值和普通数据六组兼容性。

损坏缓存回归核对旧行逐字保留、daily 修正、新结果可命中及 summary 不刷历史。失败回归先让真实向量回填写入，再抛合成异常，逐表确认 items、embeddings、修订号、旧 history 和 daily 全部保持失败前状态，并验证名额释放及后续可恢复重算。没有模型或个人数据。

新增测试在旧版为 **27 failed / 6 passed，6.59 秒**；修复后与旧评分/全库统计、历史 JSON 完整性、写入取消三个既有文件联合为 **186 passed / 1 条既有 Starlette 警告，22.22 秒**。`git diff --check` 通过。探针与旧/新日志仅留在 ignored 的 `output/playwright/quality-20261003/`。

## 保证边界

校验保证这里定义的必要字段、范围和缺失语义，不是缓存防篡改签名，也不重新扫描原始 hash/渠道来校验所有自洽数值。旧历史不迁移或清洗。既有轻量事务负责重算失败回滚；本批合成故障不替代磁盘满、断电或损坏数据库验收。独立复核、全套、真实浏览器和精确提交 CI 由主流程分别记录。
