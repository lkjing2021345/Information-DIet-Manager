# 后台轮询与显式读取的调度修复

## 问题与修复前证据

后台每 30 秒读取记录时，原实现把 `recordsLoading` 置为真。此时打开抽屉，`openRecords()` 虽然调用 `fetchRecords()`，却被加载保护直接跳过；稍后后台请求返回，又因抽屉已打开被丢弃。因此，新增记录既没有进入抽屉，也没有触发一次真正的前台刷新。设置中的刷新按钮也会被后台请求禁用。

本次先增加真实浏览器回归，再改产品代码。使用生产构建、隔离 Chromium、真实本地 API 和临时 SQLite：冻结后台已经读取到 2 条记录的响应，随后通过 `/collect` 保存第 3 条，再打开抽屉。保留真实 30 秒轮询，不替换浏览器时钟，不编造列表响应。原实现以 `Timed out: drawer opening supersedes pending background poll` 失败；服务端在冻结请求和新增记录之后没有收到抽屉的新 GET。该证据把此前的源码风险确认成可复现问题。

## 最小行为变化

- 显式读取可取消正在进行的后台轮询，并立即读取新快照。后台轮询不能抢占前台请求，前台请求之间仍串行，避免同一游标被重复追加。
- `recordsLoading` 只表示前台读取；后台请求仍由活动控制器跟踪，因此后台等待不会禁用设置中的显式刷新。
- 接收结果、处理异常与快照恢复时，同时校验请求控制器身份、数据代际、取消状态和组件是否已卸载。被取代的请求不能回写数据、触发过期恢复或改变当前错误状态。
- 只有当前控制器能结束加载状态。断开连接或数据维护会清除活动请求引用；既有退出、密钥失效与卸载取消逻辑继续生效。

没有修改模板、CSS、主题、动效、四图布局或右侧抽屉结构。原来保护已打开设置/抽屉不被后台响应覆盖的条件仍然保留。

## 验证边界

新增三个真实网络时序场景：打开抽屉抢占后台旧快照并显示随后采集的记录；设置显式刷新抢占后台，且晚到的后台完成不能提前结束新请求加载状态；调用实际 Vue 应用卸载方法后，在不导航、不关闭浏览器页的条件下确认已发出的记录请求被取消，晚到响应不会恢复私有界面。测试会释放真实旧响应并确认新结果不被覆盖，清理合成记录后继续执行既有分页、删除、恢复、断连和鉴权场景。

并发网络门控保持拦截器注册直到两次请求都完成，避免两个 `times: 1` 路由同时挂起时，Playwright 提前关闭拦截、自动放行另一请求的测试工具干扰。原来关于加载状态和快照完整性的严格断言没有放宽。

前端单元及视觉结构门禁 35 项通过；生产构建通过。主 JavaScript 包约 1234.09 kB（gzip 415.23 kB），仍有大于 500 kB 的既有构建告警。

最终完整真实浏览器生命周期回归 **29 个场景通过**。使用 Vue 单文件组件解析器对比本轮修改前的 `HEAD`，模板和全部样式块在统一换行后逐字一致。语法及差异空白检查通过。本机结果仍需对应提交的 GitHub CI 复核。

分析图表场景仍使用合成分析结果，不证明真实模型推理；本轮也不声称覆盖所有组件卸载或浏览器异常终止方式。
